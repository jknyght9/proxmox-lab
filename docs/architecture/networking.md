# Networking Architecture

## Network Topology

All Proxmox Lab VMs and containers connect to your existing LAN via a Proxmox bridge (typically `vmbr0`). The network CIDR and gateway are configured in `bootstrap.yml` and auto-detected from the Proxmox host.

```
Your LAN (<network-cidr>, gateway: <gateway-ip>)
  |
  |-- vmbr0 (Proxmox bridge)
        |
        |-- nomad01  (<nomad01-ip>)  -- Nomad, Vault, Traefik, Authentik
        |-- nomad02  (<nomad02-ip>)  -- Nomad worker
        |-- nomad03  (<nomad03-ip>)  -- Nomad worker
        |-- dns-01   (<dns01-ip>)    -- Pi-hole primary
        |-- dns-02   (<dns02-ip>)    -- Pi-hole secondary
        |-- dns-03   (<dns03-ip>)    -- Pi-hole tertiary
        |-- kasm01   (<kasm-ip>)     -- Kasm Workspaces (optional)
```

## IP Allocation

IPs are configured in `terraform/terraform.tfvars` (generated by bootstrap). The following structure is typical with HA enabled:

```
<gateway-ip>      Gateway (router)
<network>.2       Reserved
<network>.3       keepalived VIP (DNS failover endpoint, if HA enabled)
<network>.4       dns-01
<network>.5       dns-02
<network>.6       dns-03
<network>.7+      Other services
<network>.100+    Traefik HA VIP (if HA enabled)
<dhcp-range>      Nomad VMs, Kasm (DHCP or static — configured in terraform.tfvars)
```

## DNS Architecture

### Resolution Chain

```
Client
  |
  v
Pi-hole (ad blocking, local DNS records)
  |
  |-- local records:  return internal IP immediately
  |-- blocked:        return 0.0.0.0
  |-- external:
        v
     Unbound (validates DNSSEC, DNS-over-TLS)
        |
        v
     Cloudflare (1.1.1.1) or Quad9 (9.9.9.9) via TLS
```

### Pi-hole v6 Configuration

Pi-hole v6 uses the FTL (Faster Than Light) engine with a TOML configuration file at `/etc/pihole/pihole.toml`. Local DNS records are stored in the `dns.hosts` array.

!!! note "Pi-hole v6 API"
    Pi-hole v6 uses a new REST API at `/api/`. The old PHP-based API from v5 is no longer available. DNS records are managed via `pihole-FTL --config` and Pi-hole CLI rather than the old Terraform provider.

### Gravity Sync

DNS configuration is replicated between Pi-hole nodes using Gravity Sync:

- `dns-01` is the primary (Gravity Sync source)
- `dns-02`, `dns-03` sync from `dns-01` every 5 minutes
- Gravity Sync replicates Pi-hole configuration, block lists, and custom DNS records

### DNS Cluster Sizing

The number of Pi-hole nodes matches the number of Proxmox cluster nodes (one per node), up to 3. Configured in `terraform.tfvars` under `dns_main_nodes`.

## High Availability with keepalived

### DNS HA

When `ha_dns_enabled: true` is set in `bootstrap.yml`, keepalived VRRP is configured on all DNS nodes. A virtual IP (VIP) floats to the highest-priority healthy node.

```
Client DNS: <dns-ha-vip>

dns-01 (priority 101, MASTER)   -- VIP bound here by default
dns-02 (priority 100, BACKUP)   -- takes VIP if dns-01 fails
dns-03 (priority 99,  BACKUP)   -- takes VIP if dns-01 and dns-02 fail

Failover trigger: Pi-hole FTL health check fails on master
```

Configuration in `bootstrap.yml`:

```yaml
ha_dns_enabled: true
ha_dns_vip: "<vip-ip>/24"        # e.g., "192.168.1.3/24"
ha_dns_vrrp_router_id: 51        # Unique ID, must not conflict with other VRRP
ha_dns_vrrp_password: "pihole1"  # Max 8 characters
```

Verification:

```bash
# Check VIP is on the master
ssh labadmin@dns-01 "ip addr show eth0 | grep <vip-ip>"

# Test failover
ssh labadmin@dns-01 "sudo systemctl stop pihole-FTL"
# VIP should move to dns-02 within a few seconds

# Verify DNS still responds
dig @<vip-ip> google.com

# Restore
ssh labadmin@dns-01 "sudo systemctl start pihole-FTL"
```

### Traefik HA

When `ha_traefik_enabled: true` is set in `bootstrap.yml`, keepalived VRRP is configured on all Nomad nodes. Traefik runs as a system job (on all nodes), and the VIP floats to the highest-priority node with a healthy Traefik instance.

```
Clients --> <traefik-ha-vip>:443 --> Traefik (active) --> Services

nomad01 (priority 101, MASTER)   -- VIP here by default
nomad02 (priority 100, BACKUP)   -- takes over on nomad01 failure
nomad03 (priority 99,  BACKUP)   -- takes over if nomad01 and nomad02 fail

Failover trigger: /ping endpoint on Traefik returns non-200
```

Configuration in `bootstrap.yml`:

```yaml
ha_traefik_enabled: true
ha_traefik_vip: "<vip-ip>/24"      # e.g., "192.168.1.100/24"
ha_traefik_vrrp_router_id: 53
ha_traefik_vrrp_password: "trafk1"
```

Verification:

```bash
# Check VIP on master
ssh labadmin@nomad01 "ip addr show eth0 | grep <vip-ip>"

# View keepalived status
ssh labadmin@nomad01 "systemctl status keepalived"

# Test failover (stop Traefik container)
ssh labadmin@nomad01 "nomad job stop traefik"
# VIP should move to nomad02

# Check logs
ssh labadmin@nomad01 "journalctl -u keepalived -f"
```

## DNS Records Created

Layer 2 Terraform creates these DNS records in Pi-hole:

| Hostname | Points to | Notes |
|----------|-----------|-------|
| `nomad01.<dns-suffix>` | nomad01 IP | Direct access |
| `nomad02.<dns-suffix>` | nomad02 IP | Direct access |
| `nomad03.<dns-suffix>` | nomad03 IP | Direct access |
| `vault.<dns-suffix>` | Traefik VIP or nomad01 | Via Traefik HTTPS |
| `traefik.<dns-suffix>` | Traefik VIP or nomad01 | Dashboard |
| `nomad.<dns-suffix>` | Traefik VIP or nomad01 | Nomad UI |
| `auth.<dns-suffix>` | Traefik VIP or nomad01 | Authentik |
| `pihole.<dns-suffix>` | Traefik VIP or nomad01 | Pi-hole admin |
| `status.<dns-suffix>` | Traefik VIP or nomad01 | Uptime Kuma (if deployed) |
| `lam.<dns-suffix>` | Traefik VIP or nomad01 | LAM (if deployed) |
| `netbox.<dns-suffix>` | Traefik VIP or nomad01 | Netbox (if deployed) |
| `kasm.<dns-suffix>` | Kasm IP | Direct (if deployed) |
| `dns-01.<dns-suffix>` | dns-01 IP | Direct |
| `dns-02.<dns-suffix>` | dns-02 IP | Direct |
| Proxmox node names | Node IPs | Auto-detected from cluster |

When HA VIPs are configured, service records point to the VIP instead of nomad01's IP.

## Configuring Clients to Use Lab DNS

Point your client's DNS server to the Pi-hole IP (or HA VIP if configured):

**Router-level (recommended):** Configure the DNS server in your router's DHCP settings so all devices on the network automatically use Pi-hole.

**Per-device:** Manually set the DNS server on each device.

**macOS example:**
```bash
# System Preferences > Network > Advanced > DNS
# Or via command line:
networksetup -setdnsservers Wi-Fi <pihole-ip>
```

**Linux example:**
```bash
# Edit /etc/resolv.conf or use systemd-resolved
echo "nameserver <pihole-ip>" | sudo tee /etc/resolv.conf
```

## Proxmox Node DNS

During deployment, the Proxmox nodes' DNS is updated to use the Pi-hole cluster:

```bash
# Set via Proxmox API on each node
pvesh set /nodes/<node-name>/dns -dns1 <dns01-ip>
```

During rollback or purge, the DNS is reset to the network gateway.

## Bootstrap DNS

The `bootstrap_dns` variable (in `terraform.tfvars`) specifies which DNS server LXC containers use during initial provisioning — before the Pi-hole cluster is available.

Some networks block external DNS servers (1.1.1.1, 8.8.8.8) and only allow DNS via the gateway. The bootstrap script automatically sets `bootstrap_dns` to the gateway IP from `bootstrap.yml`. After provisioning completes, containers switch to internal Pi-hole DNS.

If provisioning fails during `apt-get update`, this is usually the cause. Verify `bootstrap_dns` is set to a DNS server your network allows.
